# 地方版みらい議会 設計メモ

- 作成日: 2026-10-09
- 状態: たたき台（議論用）
- 画面モック: [docs/mocks/local-gikai/index.html](mocks/local-gikai/index.html)（静的HTML。ブラウザで直接開ける）

## 1. 背景と方針

地方議会（都道府県・市区町村議会）版のみらい議会を作るプロジェクトが動いている。

**方針: 自治体ごとにフォークして作るのではなく、1つのプラットフォームで複数の議会を扱う。**
議案の概要さえ登録されれば、その議会のページは自動で出来上がる状態を目指す。

フォーク方式を採らない理由:

- 改修が各フォークに分かれて戻ってこなくなる（AIインタビュー・トピック分析などの改善が全自治体に行き渡らない）
- 自治体ごとにインフラ・運用者が必要になり、小さな自治体では維持できない
- 全国横断での比較・検索・オープンデータ化ができない

したがって作るべきものは「各地方のサイト」ではなく、**議案を登録する導線**と、**登録されたデータから議会ページを出す仕組み**である。

## 2. 論点

| # | 論点 | 結論（案） |
|---|---|---|
| 1 | 概要を誰がどう書くか | 人に要約を書かせない。議案書PDFを入れると AI が議案ごとに分割・下書きし、人は確認するだけにする |
| 2 | 国会専用のデータ構造をどうするか | `assemblies`（議会）を導入し、国会もその1件として扱う |
| 3 | 権限 | 全体管理者／確認者／編集者の3役割。確認者・編集者は担当議会だけ操作できる |
| 4 | 一般からの投稿 | 議案書（PDF・写真・URL）を送るだけのフォーム。受付キューで確認してから取り込む |
| 5 | 空のページ問題 | 全国の議会マスタは持つが、公開議案がない議会は一覧に出さず、投稿を呼びかけるページにする |
| 6 | 意見の届け先 | 最初はチームみらいの地方議員がいる議会に絞って始める |
| 7 | 自動取り込み（スクレイピング） | 採らない。掲載形式が自治体ごとにバラバラで保守できない |

### 2.1 概要を誰がどう書くか（最重要）

国会版では、運営が `bill_contents`（ふつう／くわしくの2段階）と `bills.knowledge_source`（AIチャット用の参照資料）を丁寧に作っている。
地方で同じことをボランティアに求めると続かない。また地方議会は次の事情がある。

- 定例会は年4回（3・6・9・12月）、会期は2〜4週間と短い
- 議案書の公開は開会の1週間前くらい。人手で書いていては採決までに間に合わない
- 1会期分の議案が1つのPDF（数十〜100ページ超）にまとまっていることが多い
- 人事案件・路線認定など、解説の必要性が低い議案も多い

そこで登録の流れを次のようにする（モック A3・A4）。

```
議案書PDFをアップロード（1会期分まるごと）
  → AI が議案ごとに分割（番号・正式名称・種類・ページ範囲）
  → 人が解説不要な議案を外す
  → AI が議案ごとに下書き（表示タイトル・ふつう・くわしく・knowledge_source）
  → 確認者が原文と並べて確認・修正 → 公開（is_review_completed = true）
```

品質の担保:

- AI は下書きの各文について原文の根拠位置（ページ・範囲）を返す。確認画面では原文側をハイライトする
- 数値・日付・金額が原文にない場合は警告を出す
- 公開できるのは確認者だけ。公開ページには「AIが下書きし、◯◯担当の編集者が確認（日付）」と明記する

### 2.2 データモデル

現状のテーブルは国会専用の前提になっている。

| 現状 | 地方で問題になる点 |
|---|---|
| `bills.originating_house: house_enum (HR/HC)` | 一院制なので不要 |
| `bill_status_enum`（introduced → in_originating_house → in_receiving_house → enacted/rejected） | 地方は 提出 → 委員会付託 → 本会議で可決・否決・継続審査 |
| `diet_sessions` | 地方では「令和8年9月定例会」「臨時会」の単位 |
| `mirai_stances` | チームみらいの議員がいない議会では賛否を出せない |
| `bills.shugiin_url` | 議会ごとに出典URLが異なる |

追加・変更案（詳細はフェーズ0で詰める）:

```sql
-- 議会マスタ（国会も1件として持つ）
create type assembly_type_enum as enum (
  'national', 'prefecture', 'city', 'special_ward', 'town', 'village'
);
create type assembly_status_enum as enum ('master_only', 'preparing', 'public');

create table assemblies (
  id uuid primary key default gen_random_uuid(),
  slug text not null unique,              -- 'national', 'aoba-city' など。URLに使う
  name text not null,                     -- 'あおば市議会'
  type assembly_type_enum not null,
  local_gov_code text unique,             -- 全国地方公共団体コード（国会は null）
  prefecture_code text,                   -- 都道府県での絞り込み用
  status assembly_status_enum not null default 'master_only',
  official_url text,
  has_mirai_member boolean not null default false, -- 賛否欄を出すか
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
alter table assemblies enable row level security;

-- 会期・議案を議会に紐づける（既存データは national に寄せる）
alter table diet_sessions add column assembly_id uuid references assemblies(id);
alter table bills add column assembly_id uuid references assemblies(id);

-- 地方用の項目
alter table bills add column bill_number text;      -- '議案第52号'
alter table bills add column official_name text;    -- 正式名称
alter table bills add column category text;         -- 予算／条例／人事・契約／請願・陳情／その他
alter table bills add column committee_name text;   -- 付託委員会
alter table bills add column source_url text;       -- 出典（shugiin_url の一般化）
alter table bills add column source_pages text;     -- 議案書中のページ範囲
alter table bills alter column originating_house drop not null;
```

`bill_status_enum` には地方用の値（`referred_to_committee`, `continued` など）を追加し、表示ラベルは議会の種類で切り替える。
`diet_sessions` は名前が国会寄りだが、リネームは影響範囲が大きいので当面そのまま使い、別途検討する。

議案書の取り込み単位も持つ:

```sql
create table bill_import_jobs (
  id uuid primary key default gen_random_uuid(),
  assembly_id uuid not null references assemblies(id),
  session_id uuid references diet_sessions(id),
  source_file_path text not null,          -- Storage 上の議案書PDF
  source_url text,
  status text not null,                    -- splitting / drafting / completed / failed
  detected_bills jsonb,                    -- AIが分割した結果（番号・名称・ページ）
  created_by uuid not null,
  created_at timestamptz not null default now()
);
alter table bill_import_jobs enable row level security;
```

### 2.3 権限

現状の admin は「Google Workspace のユーザーは自動で管理者」で、権限は全か無かの二択。
地方版ではチーム外のボランティアを招待するため、議会単位の役割を追加する（モック A6）。

| 役割 | できること | 想定 |
|---|---|---|
| 全体管理者 | すべて。議会の追加、担当者の任命 | 運営（既存の admin ユーザー） |
| 確認者 | 担当議会の議案の登録・編集・**公開**、投稿の取り込み、賛否の入力 | チームみらいの地方議員、地域リーダー |
| 編集者 | 担当議会の議案の登録・編集（公開不可） | サポーター |

```sql
create type assembly_member_role_enum as enum ('reviewer', 'editor');
create table assembly_members (
  assembly_id uuid not null references assemblies(id),
  user_id uuid not null references auth.users(id),
  role assembly_member_role_enum not null,
  invited_by uuid,
  created_at timestamptz not null default now(),
  primary key (assembly_id, user_id)
);
alter table assembly_members enable row level security;
```

RLS ポリシーは定義せず（既存方針どおり）、認可は Server Actions / Loaders で `assembly_members` を見て判定する。

### 2.4 一般からの投稿

投稿者に求めるのは「議案書を渡すこと」だけで、要約は書かせない（モック W4）。

- 入力: 議会（候補外も可）、PDF・写真・URL、会期（任意）、ひとこと（任意）、連絡先メール（任意）
- Turnstile 等でボット検証
- 投稿は `bill_submissions` に入り、すぐには公開しない
- AI がまず「議案書か／どの議会・会期か／既存と重複していないか」を判定してから受付キューに並べる（モック A5）
- 担当者がいる議会は担当者へ、いない議会は全体管理者へ通知
- 「取り込む」で A3 の一括登録にそのまま渡す

```sql
create table bill_submissions (
  id uuid primary key default gen_random_uuid(),
  assembly_id uuid references assemblies(id),  -- 候補外の議会なら null
  assembly_name_input text,                    -- 候補外のとき投稿者が入力した名前
  source_file_path text,
  source_url text,
  session_hint text,
  comment text,
  contact_email text,
  ai_judgement jsonb,                          -- 議案書か・会期・重複候補など
  status text not null default 'pending',      -- pending / imported / rejected
  import_job_id uuid references bill_import_jobs(id),
  created_at timestamptz not null default now()
);
alter table bill_submissions enable row level security;
```

### 2.5 空のページ問題

全国の議会（約1,800）をマスタとして一括投入するが、ほとんどは空のままになる。

- 「開会中の議会」一覧には公開議案がある議会だけを出す（モック W1）
- 公開議案がない議会のページは「まだ載っていません → 議案書を送る」に置き換え、noindex にする（モック W5）
- 「公開されたら知らせて」の登録数を、次に取り組む議会を決める材料にする

### 2.6 意見の届け先

国会版のAIインタビューは、集めた声を議員に届けることに価値がある。
受け取る議員がいない議会でインタビューを開くと「答えても意味がない」と感じさせてしまう。

- 最初はチームみらいの地方議員がいる3〜5議会に絞る
- インタビュー結果（レポート・トピック分析）は既存の仕組みをそのまま議会単位で使う
- 届け先がない議会では、インタビューは出さずAIチャットだけにする選択肢も持つ（議会ごとの設定）

## 3. 画面一覧

### 公開サイト（web）

| ID | 画面 | URL案 | 要点 |
|---|---|---|---|
| W1 | 地方議会の選択 | `/local` | 開会中の議会、都道府県から探す、前回見た議会、投稿への導線 |
| W2 | 地方議会トップ | `/local/[assembly]` | 開会中の定例会と議案一覧（種類タブ）、過去の定例会 |
| W3 | 議案詳細 | `/local/[assembly]/bills/[slug]` | 概要（ふつう／くわしく）、審議の進み具合、賛否（任意）、AIチャット、インタビュー、出典と確認者 |
| W4 | 議案の投稿 | `/local/submit` | 議会選択と議案書のアップロードだけ |
| W5 | まだ始まっていない議会 | `/local/[assembly]`（公開議案なし） | 投稿の呼びかけ、公開通知の登録、noindex |

URL を `/local/...` に分けるか、国会も含めて `/[assembly]/...` に統一するかは要検討（既存URLのリダイレクトが必要になるため、まずは `/local` 配下を推奨）。

### 管理画面（admin）

| ID | 画面 | 使う人 | 要点 |
|---|---|---|---|
| A1 | 議会一覧 | 全体管理者 | 議会の状態（マスタのみ／準備中／公開中）、担当者、待っている人数 |
| A2 | 議会ダッシュボード | 確認者・編集者 | 担当議会の定例会と議案、確認待ち件数、採決結果の一括入力 |
| A3 | 議案の一括登録 | 確認者・編集者 | 議案書PDF → AI が議案ごとに分割 → 下書き生成 |
| A4 | AI下書きの確認 | 確認者・編集者 | 原文PDFと下書きを並べる、根拠ハイライト、数値の警告、公開 |
| A5 | 投稿の受付キュー | 全体管理者・確認者 | AIによる判定、取り込み／却下 |
| A6 | 担当者と権限 | 全体管理者 | メール招待、議会ごとの役割 |

## 4. 進め方

| フェーズ | 内容 | 公開への影響 |
|---|---|---|
| 0 | `assemblies` 導入、既存の会期・議案を国会に紐づけ、各クエリに議会の絞り込みを追加 | なし（国会版の見た目は変えない） |
| 1 | 議会単位の権限（A6）、PDF一括登録とAI下書き（A3・A4）、ダッシュボード（A2）。試験自治体の担当者だけで運用 | 試験議会のみ限定公開 |
| 2 | 公開サイト（W1〜W3・W5）を正式公開。3〜5議会 | 公開 |
| 3 | 一般からの投稿（W4・A5）、議会マスタの全国投入、公開通知 | 議会を広げる |
