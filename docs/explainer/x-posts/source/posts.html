01全体像

みらい議会は2つのアプリ

国会の議案をやさしく解説し、AI に質問したり、AI のインタビューで意見を届けたりできる Web サービス。

公開サイトweb/

  • 議案の一覧・会期ごとのまとめ
  • やさしい解説とふりがな、チームみらいの賛否
  • AI チャットと AI インタビュー
  • みんなの意見・トピック、オープンデータ API

管理画面（運営だけ）admin/

  • 議案の登録・解説の執筆・公開の切りかえ
  • 賛否と理由の登録（公開日時の予約）
  • インタビューの質問づくりと試運転
  • レポートの確認・トピック分析の実行

04ミスや悪用を防ぐ

コードのミスを本番の前に止める

「人が気をつける」だけに頼らず、プログラムで自動的に止める。

テスト（Vitest）

防ぐもの計算や変換のまちがい

入力と期待する出力を書いて確かめる。DB 関数はローカルの本物の Supabase で

型チェック（TypeScript）

防ぐもの「数値のはずが文字列」など

変数や引数に型を書き、実行する前に見つける

書き方（Biome）

防ぐもの書き方のばらつきとよくあるミス

コミット前に自動で整形し、ルール違反を知らせる

GitHub Actions

防ぐものチェックを通っていないコード

PR のたびに lint・型・ビルド・テストを実行

コミット前に整形→PR で自動チェック→テストと型がすべて通る→マージして本番へ＋ Codecov・CodeRabbit

04ミスや悪用を防ぐ

AI の使いすぎと悪用を防ぐ

利用料の上限

防ぐもの使いすぎや、いたずらの大量の質問

1人1日 0.5ドル、全体で1日 50ドル・1か月 1000ドル（既定）。こえたら止める。確認に失敗したときも止める

モデレーション

防ぐもの悪口や個人情報が入ったレポートの公開

別の AI が0〜100点で採点。29点以下で本人が同意したものだけ自動で公開

入力の区切り

防ぐもの「今までの指示を忘れて…」でだます攻撃

利用者の文章は毎回ランダムな区切りで囲み、指示とは別のデータとして渡す

データを守る

RLS（行レベルセキュリティ）

防ぐものブラウザから DB を直接読まれること

全テーブルで有効にして、許可のルールは書かない。読み書きは秘密の鍵を持つサーバーだけ

管理者のチェック

防ぐものスタッフ以外が管理画面に入ること

middleware がページを開くたびに admin の役割を確かめる。actions でも確認

プレビュー用のトークン

防ぐもの公開前の議案を URL だけで見られること

匿名ユーザー

防ぐもの他人のインタビューを見たり続けたりすること

メール登録なしの匿名ログイン。セッションの user_id と一致するかで本人を判定

04ミスや悪用を防ぐ

コードのルール

AGENTS.md（CLAUDE.md）に書かれている決まりごと。

page.tsx は薄く

パラメータを受けとって feature に渡すだけ。index.ts は作らない

server-only

サーバー側のファイルには "server-only"、Client には "use client"

共有は packages へ

web と admin に同じコードを置かない

アイコンは lucide-react

インライン SVG は使わない。ボタンは共通の Button

色はトークン

text-[#xxx] などの直書きは禁止。globals.css に足してから使う

リンクは routes.ts

href や redirect に文字列のパスを書かない
